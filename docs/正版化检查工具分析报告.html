一、核心结论

该工具对"安装日期"的采集完全依赖单一数据源（注册表 + systeminfo 命令输出），没有任何交叉校验。 客户端只是原样读取并上报：Windows 安装日期取自 systeminfo 的 "Original Install Date"（底层是注册表 InstallDate）；软件安装日期取自卸载注册表键的 InstallDate 值；WPS 安装日期取自 Software\kingsoft\Office\6.0\Common 的 InstallTime 值及 utility\install.ini。拥有管理员权限的用户修改这些注册表值后，客户端导出的"安装日期"即可被伪造，且工具本身无法察觉。

三、安装日期读取机制详解

检测对象数据来源具体路径 / 方法值类型与格式
Windows 安装日期 systeminfo 命令输出 cmd.exe /c systeminfo /FO LIST，解析 Original Install Date（中文系统为"初始安装日期/原始安装日期"）；同时从 HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion 读 ProductName / EditionID / CurrentBuild 等 底层为 HKLM 同名键下 InstallDate（REG_DWORD，Unix 秒），systeminfo 显示为本地时间
通用软件安装日期
（Office 专业增强版在此列）		 注册表卸载键 枚举 HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*、HKLM\SOFTWARE\Wow6432Node\...\Uninstall\*（32 位软件）、HKCU\...\Uninstall\*，读取 DisplayName / DisplayVersion / InstallLocation / Publisher / UninstallString / InstallDate / DisplayIcon InstallDate 为字符串 YYYYMMDD 或数值；代码用 %Y-%m-%d / %04d-%02d-%02d 格式化为日期
WPS 教育版安装日期 注册表 + INI 文件 Software\kingsoft\Office\6.0\Common 的 InstallTime 值；<WPS安装目录>\utility\install.ini（GetPrivateProfileStringW 读取）；辅助键 SOFTWARE\Kingsoft\WPSCloud\license（授权状态） InstallTime 为时间戳；install.ini 记录安装信息
软件版本号 文件版本资源 对目标 EXE 调 GetFileVersionInfoW / VerQueryValueW 读 \StringFileInfo\<lang>\FileVersion（如 wps.exe、WINWORD.EXE） 字符串版本号
WPS 版本/授权判定 清单 + 注册表 WPSFeatureInfos 版本号表精确匹配（教育版 11.1.0.820 / 11.3.0.9228，专业增强版 11.2.0.9453 / 10.8.2.6837 / 11.8.2.8576 等）；授权特征串"包含/不包含 WPS Office 正版授权"；内置提示"增强版(2021年4月前获得合法授权产品显示为专业增强版)" 版本号 + 状态标记

名称匹配逻辑（checkSoftList.ini 驱动）

枚举卸载键后用 DisplayName 与五类清单（OS / OFFICE / AV / CAD / DB，共 158 个关键词）做包含匹配，再经 ExcludeFeatureInfos 排除"语言包 / VBA / 插件 / Outlook / Visio / Update / Shared"等 50 个干扰词，SubStringInfos 处理互为子串的软件（ZWSim / ZWSim-EM）。最终每条输出 JSON：{"name","version","id","date","type"}。

四、可篡改性分析（核心问题）

目标字段修改位置所需权限篡改难度工具侧校验
Windows 安装日期 HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\InstallDate（REG_DWORD Unix 时间戳） 管理员 低（一条 reg 命令） 无
Office 专业增强版安装日期 卸载键下 Office 子键（形如 {90160000-...} 或 Microsoft Office 键）的 InstallDate 值 管理员（HKLM）/ 普通用户（HKCU 键） 低 无
WPS 教育版安装日期 Software\kingsoft\Office\6.0\Common\InstallTime（HKLM 需管理员，HKCU 无需）+ utility\install.ini 内容与文件时间 管理员（HKLM）/ 视安装位置 低～中（需两处同步，避免不一致） 无
结论：工具对安装日期是"读什么报什么"，无任何二次验证。既不对比安装目录文件的创建/修改时间，不查询 MSI 数据库（Win32_Product）、Windows 事件日志（MsiInstaller/Setup 事件）、更新历史或还原点。单点修改注册表即可让导出的安装日期失真。唯一的"第二来源"是 WPS 的 install.ini，但它同样是安装时写入的同一来源，只需同步修改即可保持一致。

篡改测试操作参考（在测试机上执行，勿在生产环境）

# 1) 修改 Windows 安装日期（Unix 时间戳，示例=2025-01-01 00:00 UTC+8 约 1735653600）
reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion" /v InstallDate /t REG_DWORD /d 1735653600 /f

# 2) 先查 Office 卸载键的实际子键名
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "Office" /k
reg query "HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall" /s /f "Office" /k

# 3) 修改 Office 安装日期（字符串 YYYYMMDD）
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\<Office子键>" /v InstallDate /t REG_SZ /d 20250101 /f

# 4) 查询/修改 WPS 安装日期
reg query "HKLM\SOFTWARE\kingsoft\Office\6.0\Common" /v InstallTime
reg query "HKCU\SOFTWARE\kingsoft\Office\6.0\Common" /v InstallTime
reg add "HKLM\SOFTWARE\kingsoft\Office\6.0\Common" /v InstallTime /t REG_DWORD /d 1735653600 /f
# WPS 安装目录 utility\install.ini 中的安装信息同步修改，并可选调整文件时间

# 5) 重新触发检测（重启客户端，或等服务器下发 STARTINSPECT），对比上报 JSON 中 date 字段

五、局限性与反制提示

本分析的置信度边界

结论基于：安装包完整解包（Inno Setup 5.5.7）、.NET 主程序全量反编译（ILSpy）、检测 DLL 的完整字符串表与 PE 导入表、Inno 安装脚本。DLL 内部逐行反汇编（rizin 下载被环境安全策略中断）未完成，因此"InstallDate 缺失时的兜底行为""kingsoft 键的 HKLM/HKCU 优先级"等细节以字符串证据推断，置信度高但未逐行证实。若需 100% 确认，可对 SoftwareInspectExtern.dll 的 testcppdll / GetSoftInfo 做完整反汇编或 API 监控（如 API Monitor 记录 RegQueryValueExW 调用）。

反制视角（评估工具可信度时应注意）

服务端可能存在的校验说明
历史对比同一 MAC 多次上报，安装日期异常回退/前移会被管理员发现
合理性检查软件安装日期早于系统安装日期、晚于当前时间、与版本发布时间矛盾（如 WPS 教育版 11.3.0.9228 发布晚于声称的安装日期）都可作为疑点
授权状态联动WPS 授权状态（WPSCloud\license、教育授权账号）由独立通道校验，改日期不影响授权判定，但"有正版授权却显示旧安装日期"不构成违规证据，反之亦然
主动核查管理员可现场运行 wmic product get installdate、检查 MSI 缓存 C:\Windows\Installer、事件日志等与上报值比对
修改 HKLM 的 InstallDate 会连带改变系统多处显示（如"设置 → 系统 → 关于"、部分软件授权逻辑），测试后务必还原原值。
