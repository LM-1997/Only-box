04

问题清单（9 项）

P1

内容超过一屏高度时，导出图静默截断，与预览不一致

高已修复并验证导出正确性
现象
板块内容总高超过 2208px（9:16）时，DOM 预览正常撑高滚动，导出 PNG / PSD 直接裁掉超出部分，无任何警告；连续长图只按「屏数 × 屏高」计算总高，同样被裁。
复现
情报公告正文粘贴约 60 行文本 → 预览卡片完整 → 点「导出当前屏」→ PNG 底缘 y2190 仍有文字墨点（86 px/行），第 40 行以下丢失；样本 p1-longtext.png。
位置
banner-builder.js:1897（drawModuleCard maxH=2800 硬上限）· :1949（measureCardLayout 同款上限）· :2018（exportStripPng 总高 = height × pages.length）· :2005（drawPageToCanvas 画布定高）
影响
长条内容天然容易超一屏；用户拿到的是「看起来正常但缺内容」的成品图，几乎必然翻车。
P5

PSD 导出页脚内容层永不生成（字段名错误）

高已修复并验证功能失效
现象
footer 板块在 PSD 里只有板块标题层，页脚文字（微博 / QQ 等）完全缺失。
复现
任意含页脚的文档 → 导出 PSD → 用 ag-psd 回读或 psd-tools 查看图层树：页脚组下无文字层；对文件做 UTF-16BE 字节检索「企划」0 命中。样本 p3-rich.psd。
位置
banner-builder.js:2073：(data.items || []).map(function (it) { return it.text; }) —— footer 数据字段是 data.lines（字符串数组，见 registry.js footer createDefault 与实测 itemsInDefault:false），data.items 恒为空 → textLayer 因空值返回 null。
影响
页脚是长宣图必备收尾板块，PSD 可编辑交付对设计协作场景直接失效。
P2

超长内容导出耗时 47 秒，存在卡死与重复排版浪费

中已修复并验证性能 / 稳定性
现象
60 行公告场景：单屏导出从 0.4 s 恶化到 47 s；drawRich 对同一段文本「先排版测量、再逐行绘制」各调用一次 wrapLines，长文本下重复 measure 开销放大。
复现
同 P1 样本；导出期间页面无任何进度反馈，主线程被占满，连续点击会排队叠加。
位置
banner-builder.js:897（wrapLines）· :988（drawRich 绘制前重复排版）· :1001（textBlockInfo 再次排版）
影响
大内容下浏览器接近假死体验；叠加 P1 截断后，用户长时间等待换来的仍是缺内容的结果。
P3

导出时背景图被拉伸变形，与预览的 cover 裁切不一致

中已修复并验证导出正确性
现象
DOM 预览背景 background-size:cover（等比放大居中裁切）；Canvas 导出用 drawImage(img, 0, 0, W, H) 把原图整幅拉伸到画布，比例不符时人物 / 图形变形。
复现
整条背景设 200×1200 三色带图（上红中绿下蓝）→ 空白屏导出 → 采样 y150/y1104/y2100 分别为纯红/纯绿/纯蓝（若为 cover 应全部是绿色中段）。样本 bg-stretch-probe.png。
位置
banner-builder.js:2009：ctx.drawImage(background, 0, 0, canvas.width, canvas.height)
影响
背景是长宣图最常用功能之一；用户在预览里调好的构图，导出后变形且位置对不上。
P4

「导出全部屏」无间隔连续触发下载，多屏文档会被浏览器拦截

中已修复并验证可用性
现象
循环内逐屏 toBlob → a.click()，N 屏 = N 次下载请求瞬间连发。Chrome 对非用户手势触发的多次下载只放行第一个，其余静默拦截（头部弹「已阻止下载多个文件」）。
复现
3 屏文档 → 点「导出全部屏」→ 观察下载栏；屏数越多拦截概率越高（本地 headless 环境未拦截，真实浏览器受手势策略约束）。
位置
banner-builder.js:2014–2016（exportPng 循环 + toBlob 回调内 click）· :894（downloadBlob）
影响
多屏长宣（本工具主场景）下「导出全部」大概率只拿到部分文件，用户不知道少了。
P6

画布图片为 blob: 引用：刷新即失效，恢复草稿后图片静默丢失

中已修复并验证数据持久化
现象
选图统一存 URL.createObjectURL（banner-builder.js:126 等）；草稿 JSON 只存 URL 不存图。跨会话恢复后 blob 指向已死的会话 → loadImage 静默 resolve(null) → 导出回落深色底块 / 空占位，预览缩略图同样裂图，全程无提示。
复现
选图 → 备份草稿 → 刷新页面 → 恢复草稿 → 导出：封面主视觉变成主题深色底块（采样 RGB 18,79,48）。样本 deadblob-export.png、after-restore.png。
位置
banner-builder.js:900（loadImage onerror → null）· :2083（saveDraft）· :2084（loadDraft）
影响
「备份草稿」给用户的安全感与实际行为相反；对比「我的模板」已做 blob→dataURL 快照，同一页面内两套机制不一致。
P7

预览与导出双实现漂移：半宽模块布局、卡片样式细节已不一致

低架构项 · 本轮保留架构可维护性
现象
同一文档 DOM 预览与导出图由两套代码各自实现（15 类板块 × 2）；实测差异点：① half 模块后跟 full 模块时预览可并排、导出按两行；② 票务卡片模板导出留白与预览不同；③ 字号换算用手工 2.2 倍系数（px2）而非度量。漂移只会随时间扩大。
复现
对照 preview-rich-p1.png（DOM 截图）与 p2-rich.png（导出）同板块的间距与高度。
位置
banner-builder.js:908–1993（绘制器层）vs :288–683（DOM 渲染层）· :913（px2 系数）
影响
「所见即所得」承诺打折；每改一个模板要同步两处，漏一处即新漂移。
P8

清单符号「乱码」—— 审计误报，已更正

误报更正视觉细节
更正
修复阶段字节级复核确认：原文件 :66 为 content:"✓"（UTF-8 字节 e2 9c 93，码点 10003 = U+2713 勾选符），:70 为 content:"›"（e2 80 ba，U+203A）。审计时把码点 10003 误读为 U+FFFD 替换符（实际 U+FFFD = 65533），控制台字体把 ✓/› 渲染成问号造成误判。源文件从未损坏，无需修改，未做任何改动。
教训
码点判断必须以字节级证据为准（10003 = 0x2713 = ✓），控制台显示不能作为乱码依据。
P9

字体 CDN 依赖无降级提示

低已修复并验证健壮性
现象
四套可选字体全部从 jsDelivr 在线加载；离线 / CDN 被墙时静默回退本地字体栈，导出仍可用但字形与选择器承诺不符，用户无从得知。
复现
本次测试环境屏蔽 cdn.jsdelivr.net 后复现：导出成功，字形为回退栈。
位置
banner-builder.js:19–27（ensureFont）· :31（readyFontForText catch 空处理）· constants.js FONTS（css 数组）
影响
对「字体可商用」敏感的活动主办方，交付字形可能偏离预期且不可复现。
